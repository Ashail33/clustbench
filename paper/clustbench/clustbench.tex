\begin{abstract}
Clustering algorithms are hard to compare. Published evaluations differ in
datasets, sample sizes, metrics, hyperparameters and hardware, and few report
runtime or memory in a reproducible way. We present \emph{Clustbench}, an
open-source benchmark harness that makes the comparison mechanical. A YAML
configuration expands into a Cartesian grid of tasks over synthetic,
real-world, time-series, graph and adversarial datasets with known ground
truth. Every registered algorithm, whether native Python or any executable
speaking a four-field JSON protocol, runs on the same data, and each run is
recorded as one schema-validated row holding external validity (ARI, NMI,
and inlier-only variants), internal validity and resource use. Clustbench adds
three things that existing clustering benchmarks do not provide together: a
\emph{trajectory layer} that logs every step of an iterative algorithm as a
$(\text{state}, \text{action}, \text{cost}, \Delta\text{cost})$ record;
machine-readable \emph{algorithm cards} with theoretical predictions; and a
\emph{self-extending} layer of learned algorithm selectors that retrain on the
benchmark's own output. We pair each threat to the validity of such a
benchmark with a control in the harness: post-hoc tests and
configuration-level confidence intervals, five seeds, repeated timing of the
algorithm call alone, checked data provenance, inlier-only scoring, run
isolation with time and memory limits, large-$n$ sweeps, and
leave-one-dataset-family-out evaluation of the selectors. On the controlled
release (61 algorithms, 20 dataset families, 140 tasks, 8{,}539 runs) the
Friedman test rejects equal performance ($\chi^2 = 2698$), yet a Nemenyi
critical difference cannot separate the top 15 algorithms. The best selector
beats the best single algorithm, an EM-trained graph-Laplacian mixture, by
0.05 ARI in-distribution. It loses 0.03--0.07 ARI on held-out dataset
families, where no selector differs significantly from that algorithm. Two
wider runs show where the selectors' advantage ends. A run-isolated big-data
sweep to $n = 200{,}000$, $d = 500$ and $k = 200$ measures each algorithm's
growth exponents and records 141 runs that hit a limit. An
every-algorithm-on-every-dataset run (63 algorithms, 36 dataset families,
11{,}328 runs) finds the selectors at 0.31--0.35 ARI on curved shapes, against
0.74--0.86 for graph-based methods. On real data they lead only on the
datasets in their training table; on seven real datasets they have never
seen, they tie the best single methods. The
controls also corrected four earlier results: the ``real'' time series had
silently been synthetic, BIRCH scales quadratically beyond
$n \approx 3{,}000$ in 10 dimensions, the treatment of injected outliers
reorders the leaderboard on contaminated data, and an internal validity index
needed 16\,GB at $d = 500$.
\end{abstract}

\section{Introduction}

Clustering has no single correct objective~\cite{kleinberg2002impossibility},
so the practical question \emph{which algorithm should I use on this data?}
is answered empirically. The empirical literature is fragmented. Each paper
picks its own datasets, scale, hyperparameter budget, metrics and hardware,
and wall time and memory are usually reported anecdotally if at all. A
white paper on benchmarking in cluster analysis~\cite{vanmechelen2018benchmarking}
names these problems and calls for neutral, reproducible comparisons.

The author's MEng research assignment~\cite{maharaj2024review} reviewed big-data
clustering methods, proposed a four-way taxonomy (sampling/partitioning,
ensemble, parallel/distributed and incremental methods), and benchmarked one
representative of each category: S$^5$C~\cite{matsushima2019s5c},
PWCC~\cite{alguliyev2020weighted}, MapReduce-style parallel
$k$-means~\cite{zhao2009parallel} and mini-batch $k$-means~\cite{sculley2010web}.
Its closing recommendation was a \emph{centralised database for clustering
research} that would let practitioners find the right model for their data and
infrastructure. That study's experiments were limited by compute: the full
factorial grid exceeded the available notebook quota. Clustbench turns the
recommendation into software and keeps the grid cheap to re-run.

\paragraph{Contributions.}
\begin{enumerate}
  \item \textbf{A language-agnostic harness} (\S\ref{sec:design}) that expands
  a declarative configuration into a task grid, runs any number of algorithms
  on identical data, and writes one tidy, schema-validated record per run
  together with resource measurements, average ranks and a Friedman test.
  \item \textbf{A trajectory layer} (\S\ref{sec:trajectory}) that records the
  step-by-step optimisation of iterative algorithms as state--action--reward
  tuples. To our knowledge this is the first clustering benchmark to treat the
  \emph{search process} as a first-class output.
  \item \textbf{Algorithm cards, a gap finder and a mutator}
  (\S\ref{sec:cards}) that encode each algorithm's mechanism, inductive biases
  and complexity in machine-readable form, predict cost and quality from them,
  and search the fingerprint space for regimes no registered algorithm covers.
  \item \textbf{A benchmark suite} (\S\ref{sec:suite}) of more than thirty
  dataset generators across convex, non-convex, heterogeneous-density,
  outlier-heavy, low-rank high-dimensional, real tabular, time-series, graph
  and deliberately adversarial regimes, and a registry of 59 algorithm
  implementations.
  \item \textbf{Validity controls} (\S\ref{sec:validity}) for each threat we
  identified in our own earlier results: post-hoc statistics, seed count,
  timing method, data provenance, outlier scoring, run isolation, scale, and
  selector leakage.
  \item \textbf{An empirical study} (\S\ref{sec:results}) with
  in-distribution, leave-one-dataset-family-out, out-of-distribution,
  big-data and every-algorithm-on-every-dataset evaluations, including the
  earlier results that the controls overturned (\S\ref{sec:corrections}).
\end{enumerate}
A companion paper~\cite{clustbenchalgos} describes the new algorithms
developed with the harness. This paper covers the harness, the suite and what
the benchmark measures.

\section{Related work}

\paragraph{Clustering benchmarks.} Van Mechelen et
al.~\cite{vanmechelen2018benchmarking} set out principles for neutral
benchmarking in cluster analysis. Gagolewski~\cite{gagolewski2022framework}
proposed a framework and curated battery of low-dimensional benchmark datasets
with reference partitions, distributed as a Python package that is \emph{also}
named \code{clustbench}. The two projects are independent and complementary:
Gagolewski's work is a dataset battery with reference labels, while ours is a
run harness with resource measurement, trajectory capture and learned
selection. Gagolewski's batteries could be loaded through our dataset
interface. Fahad et al.~\cite{fahad2014survey} gave an empirical taxonomy of
big-data clustering algorithms that the author's review built
on~\cite{maharaj2024review}.

\paragraph{Synthetic data with ground truth.} MDCGen~\cite{iglesias2019mdcgen}
generates multidimensional clustering datasets with controllable outliers,
noise and density. Clustbench reimplements an MDCGen-style generator and adds
shape generators (moons, circles, spirals, Swiss roll, rings), heavy-tailed and
imbalanced mixtures, and adversarial families.

\paragraph{Statistical comparison.} We follow Dem\v{s}ar's
recommendation~\cite{demsar2006statistical} of average ranks with the
Friedman test~\cite{friedman1937use} for comparing many algorithms over many
datasets.

\paragraph{Algorithm selection and meta-learning.} Choosing an algorithm from
dataset features is Rice's algorithm selection
problem~\cite{rice1976algorithm}. It has been studied as meta-learning in
general~\cite{brazdil2009metalearning,pfahringer2000landmarking} and for
clustering
specifically~\cite{desouto2008ranking,ferrari2015clustering}, including recent
AutoML systems for clustering that select algorithms from meta-features,
dataset similarity or learned
embeddings~\cite{trederTschechlov2023ml2dac,singh2024clams,bakhtyari2025clustrecnet}.
It is also used for warm-starting in AutoML~\cite{feurer2015efficient}. Clustbench's learned
routers are instances of this idea. The contribution here is the
infrastructure that makes them self-extending: the router training set
\emph{is} the benchmark output, so it grows whenever the benchmark runs.

\section{Design}\label{sec:design}

\subsection{Task grid}
A benchmark is a YAML file. Each dataset entry lists value sets for sample
size $n$, dimension $d$, target cluster count $k$, compactness and
generator-specific knobs (outlier count, noise points, density, outlier
extremity). The harness takes the Cartesian product of every list and crosses
it with a list of seeds:
\begin{lstlisting}
datasets:
  - id: mdcgen
    n_samples: [500]
    n_features: [10]
    k_targets: [3, 5]
    outliers: [0, 100]
algorithms:
  - {name: kmeans,  kind: python,   entry: kmeans,  params: {n_init: 3}}
  - {name: mine,    kind: external, entry: ./bin/run_my_algo}
seeds: [1, 2, 3]
\end{lstlisting}
A task is uniquely identified by
$(\text{dataset}, n, d, k, \text{compactness}, \text{outliers}, \text{noise},
\text{density}, \text{seed})$. Every algorithm sees the identical array for a
given task.

\subsection{Algorithm interface}
Native algorithms subclass a small abstract base class, register themselves
under a string key, and implement \code{fit\_predict(X, k)}, which returns
an \code{AlgoResult} with integer labels, an optional dictionary of
algorithm-specific extras, and an optional trajectory. External algorithms in
any language are supported through a JSON-over-stdin protocol. The harness
writes the task to a \code{.npy} file and sends
\begin{lstlisting}
{"data_path": "...", "k": 5, "params": {...},
 "artifacts_dir": "...", "labels_path": "..."}
\end{lstlisting}
on standard input. The executable writes integer labels to
\code{labels\_path} and may print a JSON object of extras to standard output.
That is the entire protocol.

\subsection{Records and resource measurement}
Each (algorithm, task) pair produces one record validated by a Pydantic schema
(Appendix~\ref{app:schema}). Resource use is measured with \code{psutil}
around the \code{fit\_predict} call \emph{only}: wall-clock time,
resident-set-size delta, user and system CPU time, and read/write bytes where
the platform exposes them. Label saving and scoring happen outside the timed
window (\S\ref{sec:validity}). Metrics are computed by one function shared by all algorithms:
ARI~\cite{hubert1985comparing} and NMI~\cite{strehl2002cluster} against
ground truth; silhouette~\cite{rousseeuw1987silhouettes} (sub-sampled above
5{,}000 points), Davies--Bouldin~\cite{davies1979cluster} and
Dunn~\cite{dunn1973fuzzy} as internal indices; plus compactness and
separation. Because generators label injected outliers $-1$, we also report
\code{ari\_inliers} and \code{nmi\_inliers}, computed on ground-truth inliers
only. The results table is flat (one column per metric), so a
leaderboard is a one-line query in pandas or DuckDB. A crashing algorithm is
logged and skipped and does not abort the sweep. Logged failures are not
harmless, though: a missing row silently drops out of an algorithm's mean.
Section~\ref{sec:corrections} lists the root causes we found this way.

\subsection{Aggregation}
For each metric, algorithms are ranked within every task (rank 1 = best,
ties averaged). Ranks are averaged across tasks, and the Friedman
statistic is computed over the tasks on which every algorithm produced a
result~\cite{demsar2006statistical}. Because the Friedman test is nearly
always significant with dozens of algorithms, the summary also carries
post-hoc statistics (\S\ref{sec:validity}). The summary is written to
\code{summary.json} and also recomputed in the browser by the dashboard, so
adding an algorithm never requires changing analysis code.

\subsection{The trajectory layer}\label{sec:trajectory}
Iterative clustering algorithms are sequential decision processes. At each
step they observe a state (centroids, medoids, an assignment, a mixture's
parameters), take an action (reassign, move a centroid, swap a medoid, merge
two clusters), and observe a change in objective. Clustbench lets an algorithm
return a list of \code{Step} objects that are persisted as a Parquet
trajectory table with one row per step:
\[
  (\textit{run\_id}, \textit{task}, t, \; s_t, \; a_t, \; c_t, \; \Delta c_t = c_t - c_{t-1}, \; \textit{accepted}_t).
\]
Here $s_t$ is a numeric state snapshot, $a_t$ is a typed action (e.g.\
\code{\{"type": "swap", "out": 17, "in": 42\}}), $c_t$ is the scalar
objective, and the boolean records whether a proposed action was accepted
(local-search methods such as CLARANS~\cite{ng2002clarans} reject most
proposals). The negative of $\Delta c_t$ is a natural reward. Concatenated
across runs, trajectories are a dataset for value models over
$(s, a) \mapsto \Delta c$, for learned proposal distributions, and for
imitation learning of clustering policies. The companion
paper~\cite{clustbenchalgos} trains such a policy. In the current release, 45
of the 61 benchmarked algorithms emit trajectories, and the in-distribution
run stores 6{,}300 of them. Figure~\ref{fig:traj} shows three.

\subsection{Algorithm cards, gap finder and mutator}\label{sec:cards}
Each registered algorithm has an \emph{algorithm card}: its taxonomy family,
a set of mechanism tags (e.g.\ \code{kpp\_init}, \code{graph\_laplacian},
\code{posterior\_weighting}), a set of inductive biases (e.g.\
\code{convex\_clusters}, \code{non\_convex\_capable}, \code{needs\_k}),
callables for time and memory complexity in $(n, d, k)$, a hyperparameter
space, and whether $k$ is an input. Cards serve three purposes.
\begin{itemize}
  \item \textbf{Theoretical predictions.} Every result row carries three
  predicted columns (\code{theoretical\_*}: wall time, memory and an ARI
  upper bound) next to the measured values. Against the earlier timing
  method, which included scoring (\S\ref{sec:corrections}), predicted wall
  time landed within $0.6$--$1.5\times$ of measured for every algorithm, and
  the deviations were diagnostic: mean shift's ratio of 0.59 showed that its
  card's $O(n^2)$ is pessimistic for the bin-seeded implementation. The cards
  have not yet been recalibrated against the corrected timings.
  \item \textbf{Gap finding.} Given dataset fingerprints (effective
  dimension, convexity, outlier fraction, density skew and similar), the gap
  finder scores every card's predicted ARI upper bound and reports regimes
  where the best card falls below a threshold. Those regimes become new
  datasets.
  \item \textbf{Mutation.} The mutator applies four operators
  (\code{swap\_mechanism}, \code{add\_bias}, \code{crossover},
  \code{stack}) to cards and keeps candidates whose predicted mean ARI beats
  the best existing card by at least 0.02. The top candidate in a 200-step
  random search was implemented and benchmarked~\cite{clustbenchalgos}.
\end{itemize}
The card predictions are an \emph{ordering} heuristic, not a calibrated
estimate. The mutator predicted $0.926$ ARI for its proposed hybrid, which
actually reached $0.747$ (\S\ref{sec:discussion}).

\subsection{Validity controls}\label{sec:validity}
An earlier version of this paper listed threats to validity without
addressing them. Each now has a control in the harness
(Table~\ref{tab:controls}), switched on in all configurations used below.

\paragraph{Statistics.} With $k \approx 50$ algorithms the Friedman test is
over-powered: it says that \emph{some} algorithms differ, not which. The
\code{stats} module adds three things on top of it:
\begin{itemize}
  \item the Nemenyi critical difference (CD) for average
  ranks~\cite{demsar2006statistical};
  \item Wilcoxon signed-rank tests between pairs of algorithms with Holm
  step-down correction, run between every pair of the top ten and between the
  best algorithm and every other;
  \item percentile bootstrap confidence intervals for each mean, resampling
  dataset \emph{configurations} so that the five correlated seeds of a
  configuration move together.
\end{itemize}

\paragraph{Timing.} Only \code{fit\_predict} is timed. Previously the timed
window also contained label I/O and metric computation, including the
$O(n^2)$ silhouette. An untimed warm-up call per algorithm absorbs one-off
costs: the learned selectors train on first use, which had added up to 14\,s
to the first task. Each run is timed three times and the median is reported
(all three are kept). BLAS and OpenMP are pinned to one thread through
\code{threadpoolctl}, and the manifest records CPU model, core counts,
memory, package versions, git commit and a hash of the configuration.

\paragraph{Provenance.} Every row records \code{dataset\_source}
(\code{real}, \code{synthetic} or \code{synthetic\_fallback}), and with
\code{strict\_provenance} the harness refuses a real dataset whose loader fell
back to synthetic data. The UCR loader now downloads the archive's canonical
zips, verifies a pinned SHA-256, and concatenates the TRAIN and TEST splits.

\paragraph{Isolation.} Large sweeps fail in ways a small grid never shows: a
single run can exhaust memory and have the whole sweep killed by the
operating system, or block in native code that a Python alarm cannot
interrupt. With \code{resources.isolate} set, each run executes in a child
process forked from the warmed-up harness. The child limits its own address
space to its baseline plus a budget (3\,GB below), and the parent kills it
when a per-algorithm time limit expires. Runs that hit a limit are recorded
as \code{Timeout}, \code{MemoryError} or \code{Killed} rows with the task
key, so a slow or memory-hungry algorithm appears as a
did-not-finish result instead of silently disappearing from its mean.

\paragraph{Selector leakage.} All learned selectors read their training table
through one module, which can exclude dataset families. A
leave-one-dataset-family-out (LOFO) script retrains every selector without
the test family, one family at a time.

\subsection{Dashboard and continuous evaluation}
A static, dependency-free HTML dashboard served from the repository's
\code{docs/} folder reads the results and trajectory JSON. It shows
per-algorithm comparisons, a filterable per-task leaderboard, rank and
Friedman tests computed in the browser, and a trajectory viewer. Further
panels show the every-dataset run by dataset group, the big-data scaling
table, graph clustering at $n = 100{,}000$ and the held-out split. A build
script converts any run directory into dashboard JSON, so refreshing the
public leaderboard is one command plus a commit.

\section{The benchmark suite}\label{sec:suite}

\paragraph{Datasets.} Generators share one contract,
$\text{DataSpec} \mapsto (X, y)$, with $y = -1$ for injected outliers and
noise. They fall into six groups.
\begin{itemize}
  \item \emph{Convex and near-convex synthetic:} isotropic blobs, an
  MDCGen-style mixture~\cite{iglesias2019mdcgen} with outlier, noise and
  density knobs, sheared (anisotropic) blobs, imbalanced blobs, hierarchical
  nested Gaussians, and heavy-tailed Student-$t$ mixtures.
  \item \emph{Non-convex synthetic:} moons, concentric circles, spirals, Swiss
  roll, S-curve, rings and mixed shapes.
  \item \emph{Heterogeneous density and contamination:} varying density and
  \code{extreme\_outliers}, which uses a tunable outlier extremity.
  \item \emph{Low rank in high dimension:} an inverse-PCA generator that places
  cluster means in a low-dimensional latent space and projects them to
  50--200 ambient dimensions.
  \item \emph{Real tabular data:} Iris~\cite{fisher1936use}, Wine, Breast
  Cancer, Digits (projected to 16 dimensions), Olivetti faces, Glass,
  Vehicle, Segment, Yeast and E.~coli~\cite{dua2019uci}.
  \item \emph{Other modalities:} time series (UCR
  ECG200 and Trace~\cite{dau2019ucr}, plus a synthetic set) reduced to a
  16-dimensional summary of 8 statistics, 4 FFT magnitudes and 4
  autocorrelations; graph nodes (Zachary's karate
  club~\cite{zachary1977information} and a stochastic block
  model~\cite{holland1983stochastic}) reduced to 6 centralities and 10
  Laplacian eigenvectors.
  \item \emph{Adversarial:} \code{PowerLawStudentT} (anisotropic Student-$t$
  components with Zipf-distributed masses, whose first two moments look
  Gaussian) and \code{VariableDensityBridges} (dense cores with Cauchy tails
  joined by thin Poisson bridges, so no single $\varepsilon$ works). Both were
  designed specifically to break the learned selectors.
\end{itemize}

\paragraph{Algorithms.} The registry holds 50 implementations. The classical
baselines are $k$-means with $k$-means++ seeding~\cite{lloyd1982least,arthur2007kmeanspp},
mini-batch $k$-means~\cite{sculley2010web}, MapReduce-style parallel
$k$-means~\cite{zhao2009parallel}, BIRCH~\cite{zhang1996birch}, Ward
agglomerative~\cite{ward1963hierarchical}, Gaussian mixtures via
EM~\cite{dempster1977maximum}, spectral clustering~\cite{ng2002spectral},
DBSCAN~\cite{ester1996density}, OPTICS~\cite{ankerst1999optics}, mean
shift~\cite{comaniciu2002mean}, CLARANS~\cite{ng2002clarans},
Chameleon~\cite{karypis1999chameleon}, an unweighted consensus vote,
PWCC~\cite{alguliyev2020weighted} and S$^5$C~\cite{matsushima2019s5c}. The
last four of the thesis's representatives (parallel $k$-means, mini-batch,
PWCC and S$^5$C) cover its four taxonomy categories. The remaining entries are
new algorithms described in the companion paper~\cite{clustbenchalgos}:
basis-mixture models, targeted fixes, synthesised pipelines, a graph-native
method, ten learned selectors and a behaviour-cloned agent.

\paragraph{Evaluation splits.}
\begin{itemize}
  \item \emph{In-distribution} (\code{benchmark.paper.demo.yaml}): 28 task
  variants from 20 dataset families (inverse-PCA restored), seeds
  $\{1,\dots,5\}$, $n \le 1000$, giving 140 tasks.
  \item \emph{Leave-one-family-out} (\code{scripts/router\_lofo.py}): the same
  140 tasks, with each selector retrained without the family under test.
  \item \emph{Out-of-distribution} (\code{benchmark.unseen.yaml}): seven
  configurations with $(n, d, k)$ tuples, outlier extremities and seeds
  ($100$--$104$) absent from training, e.g.\ MDCGen at $d{=}25, k{=}7$, moons
  embedded in $d{=}5$, inverse-PCA at $d{=}150$, and outlier extremity 10,
  giving 35 tasks for all 62 algorithms (the 61 above plus Chameleon).
  \item \emph{Large-$n$} (\code{benchmark.scaling.large.yaml}): MDCGen
  ($d{=}10, k{=}5$) and moons at $n \in \{10^3, 3\cdot10^3, 10^4,
  3\cdot10^4, 5\cdot10^4\}$, two seeds, 18 algorithms.
  \item \emph{Big data} (\code{benchmark.bigdata.yaml}): MDCGen along three
  one-factor axes through $n{=}10^4, d{=}20, k{=}10$, namely
  $n \in \{2\cdot10^3, \dots, 2\cdot10^5\}$, $d \in \{5, \dots, 500\}$ and
  $k \in \{3, \dots, 200\}$, plus a $10^5 \times 100 \times 50$ corner; one
  seed, 120\,s and 3\,GB per isolated run, 61 algorithms.
  \item \emph{Every dataset} (\code{benchmark.shapes.yaml}): every dataset
  generator. The twenty shape and mixture generators run at $n = 2000$, both
  in their native two or three dimensions and padded to $d = 10$ (rings and
  spirals also at two values of $k$). Every real dataset runs at close to
  native size. Three seeds, isolated runs, 63 algorithms, 180 tasks.
\end{itemize}

\section{Results}\label{sec:results}

All numbers below come from the data committed in the repository
under \code{docs/}: the in-distribution, unseen and scaling runs and the
LOFO results. The figures are regenerated from those
files by the script \code{make\_figures.py} in \code{paper/scripts}. Every real
dataset loaded as real data: 2{,}135 in-distribution rows are \code{real}
and none is a fallback.

\subsection{Overall leaderboard}
The in-distribution run covers 61 algorithms on 140 tasks, giving 8{,}539
result rows. Over the 139 tasks every algorithm completed, the Friedman test
gives $\chi^2 = 2698$ ($p < 10^{-300}$). Figure~\ref{fig:ranks} shows average
ranks and Figure~\ref{fig:ci} adds confidence intervals.
\begin{itemize}
  \item \textbf{Nemenyi cannot separate the top of the board.} The CD is 8.7
  ranks, and fifteen algorithms are within one CD of the best:
  \begin{itemize}
    \item seven learned selectors;
    \item LMM and spectral clustering;
    \item the tri-basis mixtures TBMM and TBMM-FL;
    \item the micro-cluster-graph variants \code{lmm\_mcg\_dual} and
    \code{lmm\_mcg};
    \item AURA-v3 and PWCC with diverse bases.
  \end{itemize}
  \item \textbf{Pairwise tests are sharper.} Holm-corrected Wilcoxon tests
  distinguish 76 of the 96 pairs tested.
  \begin{itemize}
    \item The best selector beats LMM by 0.051 ARI (Holm $p = 2\times10^{-4}$)
    and the best micro-cluster variant by 0.046 ($p_\text{Holm} = 2\times10^{-4}$).
    \item Selector v3 beats selector v1 ($p_\text{Holm} = 0.003$).
    \item LMM and spectral clustering are indistinguishable
    ($p_\text{Holm} = 1$).
  \end{itemize}
  \item \textbf{Intervals are wide.} Configuration-level 95\% bootstrap
  intervals are about $\pm 0.09$ ARI. For example, the best selector scores
  0.815 [0.727, 0.894] and LMM 0.765 [0.661, 0.857]. Most of this width
  is \emph{between-configuration} variability, so twenty families are not
  enough to rank closely matched algorithms with confidence.
  \item \textbf{Seed variability is moderate but uneven.} The mean
  across-seed standard deviation of ARI within a configuration is 0.045 for
  LMM, 0.081 for $k$-means and 0.144 for auto-$\varepsilon$ DBSCAN.
\end{itemize}

\subsection{No algorithm dominates}
Figure~\ref{fig:heatmap} breaks ARI down by dataset family. Among the 51
non-selectors, 35 different algorithms are best on at least one family.
\begin{itemize}
  \item \emph{Convex-only} methods ($k$-means family, BIRCH, Ward) score
  $\approx 0$ on circles.
  \item \emph{Graph-Laplacian} methods (spectral, LMM, AURA) solve circles,
  but spectral and LMM reach only about 0.63 on moons. The micro-cluster
  graph methods of the companion paper reach 0.98--0.99 there, close to
  \code{louvain\_knn} (1.00).
  \item \code{louvain\_knn} is best on the karate graph (0.73) and Digits
  (0.55), but weak on imbalanced blobs (0.57) and power-law Student-$t$
  mixtures (0.50).
  \item Gaussian mixtures win Iris (0.90) and Wine (0.58).
  \item Real time series are hard for everyone. On ECG200 the best method (a
  mixture on Fourier, Laplace and Hilbert transform features) reaches
  0.36 ARI, and on Trace the best reaches 0.66.
\end{itemize}

\subsection{Outlier scoring changes the ranking}
Fifteen tasks contain injected outliers (label $-1$). Plain ARI treats them as
an extra true cluster, so an algorithm is rewarded for isolating outliers
together and penalised for absorbing them into the nearest cluster.
Restricted to inliers, the picture changes:
\begin{itemize}
  \item LMM rises from 0.733 to 0.990 and spectral from 0.723 to 0.989, while
  GMM falls from 0.702 to 0.668. The micro-cluster graph methods rise less
  (\code{lmm\_mcg} from 0.729 to 0.937).
  \item On these tasks the inlier-only ranking is led by LMM and spectral
  ($\chi^2 = 380$), whereas the plain-ARI ranking is led by the selectors.
\end{itemize}
Which convention is right depends on the application. A benchmark should
report both, because the choice decides the winner on contaminated data.

\subsection{Failure modes are few and recurrent}
The algorithm analysis bundled with the repository diagnoses each algorithm
along scaling, clean-data quality, outlier robustness and shape adaptability.
Six failure modes account for almost every weakness: outlier sensitivity of
mean-based updates, non-convex shape failure of Voronoi-cell methods,
super-linear scaling, hyperparameter brittleness, local-minimum search, and
wrong data assumptions. Because the harness runs originals and variants side
by side, it can test whether a diagnosed fix helps. Table~\ref{tab:fixes}

\subsection{Scaling beyond the CI grid}\label{sec:scaling}
Figure~\ref{fig:scaling} shows the large-$n$ sweep. Above $n = 3{,}000$ on
10-dimensional MDCGen:
\begin{itemize}
  \item \textbf{BIRCH is not linear.} Its log--log slope is 2.1, and it takes
  143\,s at $n{=}50{,}000$. With the default threshold the CF-tree grows too
  many leaves in 10 dimensions, so the global step dominates. On 2-d moons it
  stays linear. Our earlier claim that BIRCH was ``the only honest linear
  scaler'' came from the $n \le 2000$ grid.
  \item \textbf{LMM scales far better than spectral clustering on the same
  graph Laplacian.} LMM's slope is 1.5 against 2.9 for spectral, giving 6\,s
  against 297\,s at $n{=}30{,}000$, with ARI 1.00 for both.
  \item \textbf{Several methods stay near-linear:} mini-batch $k$-means
  (slope 0.5), streaming coresets (0.9), FMM (1.0), GMM (1.0) and AURA-v3's
  Nyström path (1.1).
  \item \textbf{Auto-$\varepsilon$ DBSCAN collapses at large $n$} (ARI 0.01
  above $n = 30{,}000$), while \code{louvain\_knn} keeps moons at 1.00 up to
  $n = 50{,}000$.
\end{itemize}
Capped runs (Ward and robust mean shift above $10^4$, OPTICS above
$3\cdot10^3$, quadratic methods above $3\cdot10^4$) are logged as skips.
Across the 5{,}694 in-distribution runs longer than 10\,ms, the median
coefficient of variation of the three timing repeats is 5.4\% (90th
percentile 15.6\%). Differences in wall time below about $1.3\times$ should
therefore not be read as real.

\subsection{Big data: growth in \texorpdfstring{$n$, $d$ and $k$}{n, d and k}}\label{sec:bigdata}
The big-data sweep runs all 61 algorithms with run isolation, 120\,s and 3\,GB
per run. Of 671 runs, 530 finished; 78 hit the time limit, 60 the memory
limit and 3 a \code{max\_n} cap. Figure~\ref{fig:bigdata} plots wall time
along each axis, and the repository's scaling table lists each algorithm's
log--log growth exponent in $n$, $d$ and $k$.
\begin{itemize}
  \item \textbf{Nineteen algorithms finish $n = 200{,}000$.}
  \begin{itemize}
    \item Fast and exact: mini-batch $k$-means (3.6\,s, ARI 1.00), Trident
    (3.4\,s, 1.00) and GMM (2.8\,s, 0.96).
    \item The micro-cluster graph method \code{mcg\_cf}: 1.1\,s, 1.00.
    \item Slower but complete: $k$-means and FMM (28--37\,s).
  \end{itemize}
  \item \textbf{Only 13 finish the $10^5 \times 100 \times 50$ corner.} The
  accurate ones:
  \begin{itemize}
    \item \code{mcg\_cf}: 1.00 in 1.3\,s;
    \item Trident: 0.99 in 3.5\,s;
    \item streaming coresets: 1.00 in 18.5\,s;
    \item GMM: 0.97 in 64\,s;
    \item LMM: 1.00 in 102\,s.
  \end{itemize}
  \item \textbf{Graph and hierarchical methods are quadratic in $n$.} Ward
  (exponent 2.36), density peaks (2.29), spectral (2.18) and BIRCH (2.01)
  never finish beyond $n = 10^4$. The learned selectors inherit their
  candidates' cost (exponents 1.3--1.8), and none reaches $2\cdot10^5$.
  LMM's exponent is 1.53.
  \item \textbf{Cost in $k$ separates the families.} Lloyd-type $k$-means
  variants grow with exponents 1.5--1.9 ($k$-means takes 83\,s at $k = 200$). Ward
  and BIRCH are almost flat in $k$ and reach ARI 1.00 at $k = 200$ in about
  4--5\,s.
  \item \textbf{Dimension costs memory more than time.} Most exponents in
  $d$ are below 0.6. The FLH transform-feature mixtures fail at
  $n \ge 5\cdot10^4$ because one feature block allocates an
  $n \times 300 \times d$ tensor.
\end{itemize}
The sweep uses one seed per configuration, so it measures cost, not small
differences in accuracy.

\subsection{Every algorithm on every dataset}\label{sec:shapes}
The every-dataset run asks a practitioner's question: on data of a given
\emph{kind}, which methods work? It runs 63 algorithms on all 36 dataset
generators, 11{,}328 runs in total. Only 12 did not finish, all of them mean
shift on the 64-dimensional Digits and 50-dimensional Olivetti faces; they
count as ARI 0. Figure~\ref{fig:shapes} summarises it by dataset group.
\begin{itemize}
  \item \textbf{Curved shapes split the field.} On moons, circles, rings,
  spirals, the S-curve and the Swiss roll:
  \begin{itemize}
    \item Graph-based methods lead. The four micro-cluster graph methods
    score 0.80--0.86; spectral clustering and LMM 0.74--0.78.
    \item Centroid methods score 0.21--0.26, and the main selectors (v1--v5,
    v7, v8) 0.31--0.35.
    \item Circles are 0.00 for $k$-means, GMM and selector v3.
  \end{itemize}
  The selectors were trained on families where a centroid method is often
  right, and they keep choosing one here.
  \item \textbf{Mixtures favour full-graph mixture models.} On mixed shapes,
  density bridges, nested and heavy-tailed mixtures, TBMM, LMM and spectral
  clustering lead (0.78--0.79).
  \item \textbf{Convex blobs favour GMM and $k$-means} (0.79--0.80).
  \item \textbf{Density, imbalance and outliers favour hierarchical
  summaries.} BIRCH, \code{mcg\_cf} and Ward lead (0.68--0.69).
  \item \textbf{Real data favours the selectors only where they have seen it.}
  Over all fourteen real datasets the best selector leads (0.49 against 0.40
  for GMM, the best single method). Seven of them (Iris, Wine, Breast Cancer,
  Digits, ECG200, Trace, karate) are in the selectors' training table, at
  other sizes and dimensions; there the selectors score 0.68 against 0.52.
  On the seven they have never seen (E.~coli, Glass, Yeast, Vehicle, Segment,
  Olivetti faces, 20 Newsgroups) they score 0.30, level with the best single
  methods (0.30, streaming coresets). This is the leave-one-family-out result
  of \S\ref{sec:ood} on real data.
\end{itemize}
The overall order depends on the mix of dataset kinds. Over all 180 tasks the
micro-cluster method \code{lmm\_mcg\_dual} leads (0.684), and the best
selector ranks 16th (0.580). That reverses the in-distribution ranking. A
benchmark's headline winner is a statement about its dataset mix, so we
report both splits and the per-group view.

\subsection{Generalisation of the learned selectors}\label{sec:ood}
The selectors are trained on benchmark results. Their in-distribution
scores drop only an exact fingerprint match, so sibling seeds of the same
configuration stay in the training set. Two stricter evaluations measure the
cost of that leakage.

\paragraph{Leave one dataset family out.} Retraining each selector without the
family under test lowers its mean ARI over the same 140 tasks:
\begin{itemize}
  \item v1 from 0.788 to 0.728, and v3, v5 and v7 from 0.815 to 0.745;
  \item v8 from 0.808 to 0.748;
  \item v4, the most robust, from 0.814 to 0.784.
\end{itemize}
The losses are concentrated in families whose winner is unusual. When moons
is held out, v3 can no longer learn to dispatch to \code{louvain\_knn} and
loses 0.70 ARI there; the karate graph costs 0.32. Against LMM and spectral
clustering on the same 140 tasks, no LOFO selector differs significantly
(paired Wilcoxon, Holm $p \ge 0.07$). Their mean differences range from
$-0.037$ to $+0.020$.

\paragraph{Unseen configurations.} On the out-of-distribution split
(Figure~\ref{fig:ood}), the four micro-cluster graph methods lead by mean ARI
(0.890--0.925). They are followed by TBMM (0.869), spectral clustering
(0.860), LMM (0.858), \code{louvain\_knn} (0.846) and selectors v3, v5 and v7
(0.845). None of the differences among these is significant after Holm
correction, and with 35 tasks the CD is 17.6 ranks.
These seven configurations are on average easier than the in-distribution
families (most algorithms sit above the diagonal in Figure~\ref{fig:ood}), so
the split tests transfer of the dispatch rule rather than difficulty.

\paragraph{Summary.} In-distribution, the best selector is significantly
better than any single algorithm. On families or configurations it has not
seen, it is statistically tied with LMM and spectral clustering. Its
advantage comes from having seen a family's winner, which is exactly what LOFO
removes.

\subsection{The self-extending loop}
Clustbench's learned selectors read the committed results table when first
used, so adding an algorithm and re-running the benchmark retrains them with
no code change. In the development history~\cite{clustbenchalgos}, adding the
graph-community algorithm \code{louvain\_knn} after the karate graph exposed
a gap was enough for every fingerprint selector to dispatch to it there on
the next run, raising the best selectors' mean ARI by 0.03--0.04. The LOFO
result above is the other side of the same mechanism: a selector can only
dispatch to a family's winner if it has seen that family.

\section{Corrections to earlier results}\label{sec:corrections}
The controls changed or invalidated several results reported in an earlier
draft of this paper and in the repository's analysis notes.
\begin{enumerate}
  \item \textbf{The UCR time series were synthetic.} Both UCR mirrors in the
  loader had gone dead (a 404 and a 44-byte page), so ECG200 and Trace had
  silently been replaced by noisy sinusoids, on which most algorithms scored
  ARI 1.0. On the real series even the best of the 61 algorithms now
  benchmarked reaches only 0.36 on ECG200 and 0.66 on Trace. The conclusion that ``engineered features make time series
  easy'' does not hold.
  \item \textbf{BIRCH does not scale linearly} in 10 dimensions beyond
  $n \approx 3{,}000$ (\S\ref{sec:scaling}).
  \item \textbf{Selectors do not collapse off-distribution once trained on
  the broader grid.} The earlier draft reported that the top selectors lost
  0.11--0.13 ARI on unseen configurations and that the simplest selector
  generalised best. Trained on the five-seed grid with inverse-PCA restored,
  v3 scores 0.845 on the unseen split, level with LMM, and v1 no longer
  leads.
  The robust conclusion is the LOFO one: selectors are tied with the best
  single algorithms on unseen families.
  \item \textbf{Silent failures.} Missing rows drop out of an algorithm's mean,
  so we root-caused every logged failure:
  \begin{itemize}
    \item GMM's covariance went singular on Breast Cancer. This removed GMM,
    PWCC-diverse and every selector that dispatched to GMM on 4 of 5 seeds.
    GMM now retries with more regularisation.
    \item The unseen configuration wrote \code{reg\_covar: 1e-4}, which YAML 1.1
    reads as a \emph{string}, so GMM had never produced an out-of-distribution
    result.
    \item Selectors that dispatched to the consensus ensemble crashed because it
    had no default base set.
    \item Selector v8 trained on a git-ignored file, so in a fresh checkout it
    trained on nothing.
    \item The behaviour-cloned agent loaded its checkpoint from a git-ignored
    directory. This explains its missing round-14 results.
    \item The results Parquet file failed to write (heterogeneous
    \code{extra} column) and the error was swallowed.
  \end{itemize}
  \item \textbf{Timing included scoring.} Earlier wall times contained label
  I/O and the $O(n^2)$ silhouette, and the first task of each selector
  contained its training. Comparisons of those numbers across algorithms with
  very different runtimes are unreliable.
  \item \textbf{A metric, not an algorithm, killed the first big-data sweep.}
  The Dunn index materialised an $m^2 \times d$ distance tensor per cluster
  pair, about 16\,GB at $d = 500$. The operating system's out-of-memory
  killer then ended the whole benchmark process, and every remaining run of
  that shard was lost. It now uses pairwise-distance routines (peak about
  0.3\,GB), and run isolation confines any such failure to one row.
\end{enumerate}

\section{Discussion}\label{sec:discussion}

\paragraph{What the harness made cheap.} Re-running every algorithm on every
task is a single command, and sharded sweeps merge with one script. The
controlled rerun reported here took about two hours on four cores. Most of the
corrections above were found by the controls themselves: provenance tags,
failure logs that are now read rather than counted, and stricter splits.

\paragraph{Learning beats predicting from biases, within distribution.}
Card-based predictions order candidate mutations but are not calibrated: the
mutator's top proposal was predicted at 0.926 ARI and measured at 0.747.
Selectors trained on measured results outperform both bias arithmetic and
every single algorithm, but only on families they have seen.

\paragraph{Residual threats.}
\begin{itemize}
  \item \emph{Breadth.} Twenty families and seven unseen configurations give
  wide intervals. Most conclusions about closely matched algorithms are not
  significant, and more families, not more seeds, would tighten them.
  \item \emph{Scale.} The big-data sweep reaches $n = 200{,}000$ on one
  generator with one seed on a single machine, and distributed algorithms
  run with one worker. The every-dataset run stays at $n = 2000$.
  \item \emph{Timing.} Runs share one machine; median-of-3 timing still
  varies by 5--16\%.
  \item \emph{Hyperparameters.} Algorithms run at fixed, hand-chosen
  settings; a tuned comparison would change some rankings.
  \item \emph{Unseen split.} Its configurations are synthetic and easier than
  the in-distribution families.
  \item \emph{CI cost.} The public dashboard workflow re-runs the controlled
  configuration, now 61 algorithms, on every push to the main branch. The
  big-data and every-dataset results are committed rather than re-run.
\end{itemize}

\section{Conclusion}
Clustbench turns ``which clustering algorithm should I use?'' into a
reproducible, re-runnable measurement. It records full resource usage and the
step-by-step optimisation trajectory, ships theoretical predictions next to
measurements, and feeds its own output to selectors that improve when the
registry grows. Adding validity controls changed what we can claim. Learned
selection is significantly better than any single algorithm on families it
has seen, and statistically tied with the best graph-Laplacian methods on
families it has not. The every-dataset run makes the same point at a glance:
selectors lead on real data they were trained on, tie on real data they were
not, and fail on curved shapes, where graph-based methods are best. Big-data
runs need isolation as much as statistics: one memory-hungry metric was
enough to lose a shard. Four earlier results were artefacts of silent data
fallbacks, small $n$, missing rows and an unbounded metric. Future work is more dataset families,
tuned-hyperparameter comparisons, larger-$n$ distributed runs, importing
external dataset batteries such as Gagolewski's~\cite{gagolewski2022framework},
and using the trajectory corpus to train components inside algorithms.
